# 交接与接手

交接是一个时点的任务快照。三份长期文档和代码是可追溯来源，快照引用它们，不长期重复维护第四份文档。

## Handoff

1. 先保存本轮有价值的 H/D/K 条目。保持未完成状态真实；如果任务已经符合完成条件则按正常策略提交，否则保留未提交改动，不为交接强行制造完成提交。
2. 用 [checkpoint](runtime.md#任务-checkpoint) 保存下列信息。长期内容只引用编号，当前信息则写清：
   - 当前目标、验收条件，以及用户最后一次修正；
   - 已完成、做到一半和受阻的部分；
   - 下一步需要查看的文件/符号/记录条目；
   - 已尝试的失败路线、实际证据及重试条件；
   - 已运行的验证及没有运行的部分；
   - 第一个可执行的下一步；
   - 目前允许的操作，例如「只讨论，不修改」「允许本地提交」。
3. 执行 `handoff`，核对快照中的项目路径、生成时间、分支、HEAD、未提交和未跟踪文件。脚本只检查 Git，不执行测试，checkpoint 中的验证说明属于 agent 提供的历史记录。
4. 返回快照位置和一段短接手提示。只有用户要求另建会话、发送至其他会话或委派时才调用宿主对应工具；生成快照自身不触发这些操作。

接手提示示例：

> 请使用 dev-memory 接手此项目。先读取当前项目规则和指定的交接快照，核对本地版本与工作区，按其中引用读取相关 H/D/K 条目。简述当前目标和下一步后，在当前有效授权内继续工作。

## Resume

先确认当前用户要求，读取适用的项目规则；旧快照中的操作边界是历史信息，不能覆盖更新的限制。

核对工作目录、分支、HEAD 和未提交现场。如果 HEAD 或相关文件已变化，查看对应差异并调整计划，不把快照当作当前事实。查阅快照指定的决策及记录，不重读整个仓库或全部聊天。过去的失败路线可在条件改变、有新证据时重新评估。

检查启动、测试命令是否仍适用；只补与接续工作有关的必要验证。历史通过结果不等于当前版本通过，不为完成交接机械重跑所有检查。

同一机器的新会话可以继续使用原工作区。跨机器、跨 worktree 或干净克隆必须实际具备对应代码；未提交改动和未跟踪文件不会随着文字摘要转移。需要转移时按用户授权单独传递，不能仅凭相同 HEAD 宣称现场一致。

进程、服务和测试会话属于临时环境，接手时确认是否仍存在；快照中的命令是待核实的线索，不是无条件执行指令。缺少的事实写未知，只有影响下一步且无法从现有材料确定时才询问用户。
