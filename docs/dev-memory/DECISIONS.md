## D-001 · 2026-10-03 · 三份长期文档按信息用途划分

- 状态：已采用。
- 来源：用户在本轮前的设计讨论中要求内容正交，并确认「三份文档 + Git」。
- 选择与理由：HISTORY 保存任务变化和实际验证；DECISIONS 保存持续约束后续开发的理由；KNOWLEDGE 保存可复用经验。一个事实只在一处完整说明，其他条目用 H/D/K 编号引用，避免日后出现多份不同答案。
- 接受的代价：归类和提炼仍由 agent 判断，脚本不能保证语义质量。普通变更不一定产生决策或通用经验。
- 重审条件：真实使用出现反复无法归类的信息时，先调整边界和引用规则，再考虑改变文档数量。
- 实现入口：`SKILL.md`、`references/records.md`、`assets/templates/`。

## D-002 · 2026-10-03 · 信息及时保存，完整小任务自动提交本地 Git

- 状态：已采用。
- 来源：用户明确提出并确认「文档随有价值的信息及时更新；Git 在完成一个完整的小任务后自动提交，代码和对应记录一起保存」。
- 选择与理由：记录时机由信息价值决定，提交时机由任务完整性和实际验证决定。这样能保存过程中的重要理由，同时让一个版本能说明完整的行为变化。
- 接受的代价：任务完成边界需要 agent 判断。用户的只读、不落盘、不提交要求及已有无关改动可能阻止当轮自动保存或提交。
- 重审条件：用户或项目需要其他提交策略时，调整 `.dev-memory.json` 的 `git_policy`，保留原有工作区和暂存区。
- 实现入口：`SKILL.md` 的本地 Git 流程；`scripts/dev_memory.py` 只配置策略，不执行提交。

<a id="d-003"></a>
## D-003 · 2026-10-03 · Hook 触发检查，当前 agent 负责语义记录

- 状态：已采用。
- 来源：用户要求自动触发记录；以下运行协议由 agent 在本次实现范围内选择。
- 选择与理由：首版适配 Codex 的 SessionStart、UserPromptSubmit、Stop、PreCompact。Skill 定义记录归属和提交条件；Hook 提供上下文、检查本轮回执，并在条件满足时保存机械快照。无需另一个记录 agent 或模型 API。
- 特殊处理：Stop 完全只读，依赖宿主 `stop_hook_active` 防止重复续问；PreCompact 只在同一 session/turn 已有 `recorded` 或 `noop` 回执时保存快照。脚本无法自行理解用户的任意自然语言限制，因此无回执、只读或 plan 回合不自动落盘。
- 接受的代价：无回执的长回合可能没有压缩快照，需要靠及时记录和已有 checkpoint 接续；协议测试不能证明宿主已激活 Hook。新 Hook 仍须由用户通过 `/hooks` 审阅信任。
- 重审条件：真实宿主试用发现事件字段变化、漏触发或重复触发时，依据官方协议和实际输入调整；出现其他宿主的实际需求时再增加适配。
- 实现入口：`scripts/dev_memory.py` 的 `hook`、`acknowledge`、`merge_hooks`；详细协议见 `references/runtime.md`。
- 依据：[Codex Hooks 官方文档](https://learn.chatgpt.com/docs/hooks)，2026-10-03 核实。

## D-004 · 2026-10-03 · Handoff 使用临时快照

- 状态：已采用。
- 来源：用户要求在上下文过长时交接给新会话或 agent；临时快照的实现形式由 agent 选择。
- 选择与理由：长期事实仍按 D-001 保存。短期 checkpoint 保存当前目标、有效操作边界、进度、验证和下一步；交接时附上真实 Git HEAD 和工作区状态及文档入口，不长期维护第四份文档。
- 接受的代价：快照会过期，且不携带未提交文件、运行中的进程或完整聊天。接手者须重新核对实际现场；生成快照本身不会创建会话或派发 agent。
- 重审条件：跨工作区转移真实代码成为常见需求时，另行设计用户明确授权的数据转移流程。
- 实现入口：`references/handoff.md`；`scripts/dev_memory.py` 的 `checkpoint`、`make_handoff`、`git_snapshot`。

## D-006 · 2026-10-05 · 补充决策读取范围、意图区分与验证版本

- 状态：已采用。
- 来源：用户明确同意借鉴对比报告中的前三项建议，并要求修改 Skill。
- 适用范围与读取时机：修改 D 的检索和更新规则、H 的验证字段，或 handoff/resume 的证据处理前读取。
- 选择与理由：D 按需注明适用模块或行为及读取时机；代码现状与已批准意图冲突时保留两者及冲突证据，不能仅凭代码变化替代原决定；H 与交接区分证据入口、历史执行和本轮执行，并写明结果适用的提交或未提交工作区。这些改进帮助接手者判断该遵守什么、哪些结果仍适用。
- 接受的代价：仍由 agent 查找和判断相关记录；这些语义规则不提供自动检索、语义审计或任意版本验证保证。
- 重审条件：真实使用持续漏读相关决定，或无法识别结果适用范围时，先根据失败实例调整规则，再评估工具支持。
- 实现入口：`SKILL.md`、`references/records.md`、`references/handoff.md`、`assets/templates/`；借鉴来源见 [比较报告](../comparison.zh-CN.md)。
